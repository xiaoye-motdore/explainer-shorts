# explainer-shorts

You write the content. The engine handles layout, timing, camera, handwriting, doodles, sound, loudness and encoding.

## Workflow

1. **Write the script** as `<topic>.md` in the user's working folder. Use the format below; the full reference is `${CLAUDE_SKILL_DIR}/reference/format.md`. Examples: `${CLAUDE_SKILL_DIR}/examples/`.
2. **Lint it.** Fix every error. Fix warnings unless you have a reason not to.
   ```bash
   node "${CLAUDE_SKILL_DIR}/scripts/es.mjs" lint <topic>.md
   ```
3. **Preview it.** This prints the path of a contact sheet (12 frames). Look at the image before rendering: nothing overflows, every screen is balanced, doodles read clearly.
   ```bash
   node "${CLAUDE_SKILL_DIR}/scripts/es.mjs" preview <topic>.md
   ```
   For single frames, use `--at 3.5,12`.
4. **Render it.** Expect 2–3 seconds of wall time per second of video (measured on a 2-core machine without a GPU).
   ```bash
   node "${CLAUDE_SKILL_DIR}/scripts/es.mjs" render <topic>.md
   ```
   Outputs go to `explainer-shorts-out/<topic>/`: `<topic>.mp4` (with music), `<topic>.no-music.mp4` (for platform music), `<topic>.cover-9x16.png`, `<topic>.cover-3x4.png` and `<topic>.report.json`.
5. **Report back.** Give the user the duration, the file paths, and every fact or number they should double-check before posting.

The first run installs fonts and the renderer (about 120 MB) into `~/.cache/explainer-shorts`. It needs Node 20+ and ffmpeg. If no Chrome or Chromium is found, run `node "${CLAUDE_SKILL_DIR}/scripts/es.mjs" setup --browser`.

## Script format

```markdown
---
title: Why is the sky blue?
theme: night             # notebook | night | chalk | ./my-theme.css
author: your-name
---

# Sunlight is white.
# Why is the sky blue?
> Ask a physicist, get one word.

## The guess
~~It reflects the ocean?~~
~~Air is blue?~~
!! Scattering

## The rule
[rule] Scattering ∝ 1/λ⁴
= (700 / 450)⁴ ≈ 5.9
> Blue scatters ~6× more than red.
^ Rayleigh scattering
...
!! So: blue.
```

| Line | Meaning |
|---|---|
| `# text` | Hook / title line (one line each) |
| `## text` | New screen |
| `text` | Normal line |
| `> text` | Margin note |
| `- text` | Bullet |
| `~~text~~` | Wrong guess, gets struck through |
| `!! text` | Big reveal (numbers count up) |
| `[label] text` | Stamped label + text |
| `= text` | Formula, typed out |
| `^ text` | Source for the claim above it |
| `...` | Dramatic pause (music drops out) |
| ```` ```svg 1.6 ```` | Doodle drawn stroke by stroke (seconds after `svg`) |

Inline marks: `**emphasis**`, `==highlighter==`, `*handwriting*`, `` `mono` ``.

## Rules for shorts that get watched

- **Hook in the first two seconds.** Open with one or two `#` lines that pose a question or a contradiction, or with a `!!` reveal.
- **One idea per line.** Chinese: 11 characters or fewer per line reads best. English: about 24 characters.
- **One screen (`##`) is one step of the argument.** Use 3–6 screens; aim for 30–75 seconds.
- **Build to the reveal.** Use one to three `~~wrong guesses~~` right before a `!!`.
- **Every number needs a source.** Put a `^ source` line on the same screen. Never invent a source. If you could not verify a number, tell the user instead of rendering it.
- **Doodles are optional.** When one helps, keep it to 3–12 shapes. Use `stroke="currentColor"` and `fill="none"`. Mark the highlight with `class="accent"`.
- **End on a punchline** (`!!`). The engine adds the signature and credit screen.
- **Chinese:** no spaces around marks; full-width punctuation.

## Choosing a theme

- `notebook`: French school notebook, blue ink, red pen, handwriting. Warm and playful. Good for language, everyday science and history.
- `night`: dark sky, white kinetic type, gold accents, stars. Cinematic. Good for space, tech, AI and big numbers.
- `chalk`: classroom blackboard, chalk handwriting, yellow and pink chalk. Good for lessons, maths and "teacher explains" topics.
- Your own: `theme: ./my-theme.css`. A theme is one CSS file. Start from `${CLAUDE_SKILL_DIR}/examples/themes/xuan.css` and read `${CLAUDE_SKILL_DIR}/reference/themes.md`.

If the user asks for a look none of these covers (a brand palette, rice paper, a newspaper, a terminal), write a theme file instead of bending an existing one. Then preview it before rendering.
